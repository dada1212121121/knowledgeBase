# 多用户版管理员手册

> 面向部署和管理这台 knowledgeBase 的人。备份恢复与升级回滚见 [BACKUP_RESTORE.md](BACKUP_RESTORE.md)。
> 下面 `<KB_HOME>` 是数据目录(默认 `~/.kb`)。配置键都在 `config.toml`,改完 500 毫秒内热生效,
> 除非特别标明「要重启」;「管理 → 系统参数」页改的是同一份配置。

## 1. 数据放在哪

```
<KB_HOME>/
├── meta.db, lance/, sources/ …      管理员自己的知识库(升级前的老位置,不搬家)
├── system.db                        账号、角色、会话、令牌、好友、通知、授权、分享链接、两步验证、用量记账
├── spaces/<id>/                     其它每个用户一个知识库目录:meta.db、lance/、sources/、agent-workspace/
├── avatars/                         头像
└── exports/                         「导出我的数据」生成的压缩包(24 小时后自删)
```

每个用户的知识库是**物理隔离**的:自己的 SQLite、自己的向量库、自己的原件目录。
别人的数据默认只能经「分享」授权才看得到,管理员也一样——管理员默认看不到别人的笔记和原件,
只能管账号、配额、参数和审计。

唯一的例外是 `sys.inspect`(默认只给管理员):在「用户与权限」里点某个用户的「查看」,可以在浏览器里
只读查看他的知识库(文档、预览、任务、导入记录)。这个通道每次打开和每次读取都写系统审计,不能改、
不能下载原件、不能取消任务,也不对目标用户发通知;细节见 §5.1。

## 2. 首次启动与升级

- 全新部署:先起守护进程,再 `printf '%s\n' '密码' | kb auth set-password` 创建第一个管理员 `admin`。
- 从单用户版升级:**零操作**。第一次启动时旧密码被复制成管理员 `admin`(密码不变),原来的知识库成为它的库。
- 升级 / 回滚的演练脚本和注意事项见 `docs/BACKUP_RESTORE.md` §7。**升级前先做一份含原件的备份。**

命令行管账号(经本机 `kb.sock`,不需要登录):

```bash
kb user list
kb user create <登录名> --email a@x.com --role user      # 密码从标准输入读
kb user passwd <登录名或邮箱>                             # 重设密码并让他所有会话失效
kb user disable <登录名或邮箱>                            # 停用并立即踢下线;enable 恢复
```

## 3. 站点与邮件

```toml
[site]
name = "knowledgeBase"
public_url = "https://你的域名"       # 分享链接和邮件里的链接用它——一定要改成真实对外地址

[mail]
enabled = true
from_name = ""                        # 空 = 用站点名称
per_minute = 30                       # 全站每分钟最多发多少封
[mail.primary]                        # 主账号;连续失败或超日限额会自动改用 [mail.backup]
preset = "qq"                         # qq / 163 / 126 / exmail / aliyun / custom
username = "noreply@x.com"            # 同时是发件地址
```

SMTP **授权码不写在 config.toml**,放 `<KB_HOME>/secrets.toml` 的 `[mail]` 段(不是邮箱登录密码,
要在邮箱网页版里开启 SMTP 后生成)。没配好邮件时,注册页会提示「邮箱注册暂未开放」,
但管理员仍可建账号;好友 / 分享相关的通知邮件也不会发。管理员可以用能力 `mail_test` 发一封测试邮件确认配置。

## 4. 注册与账号

```toml
[accounts]
registration_open = true              # 开放邮箱注册;关了只能管理员建账号
require_invite = false                # 注册要邀请码
default_role = "role_user"            # 新用户默认角色
username_required = true
invites_per_user = 0                  # 普通用户能生成几个邀请码(0 = 只有管理员)
block_disposable_email = true         # 拦一次性邮箱
email_domain_allowlist = []           # 只允许这些邮箱域名(空 = 不限制)
deletion_cooling_off_days = 7         # 用户申请注销后的反悔期(1–365 天)
require_admin_totp = false            # 管理级账号必须开两步验证
```

- 用邀请码注册可以**自动加邀请人为好友**。
- 用户注销有冷静期,期间可撤销;到期后清掉他的账号、知识库、授权、分享链接、头像、导出包。
- 「导出我的数据」每人每天 3 次,生成的包 24 小时后自动删除。

## 5. 角色与功能权限

内置两个角色:`role_admin`(全部功能)和 `role_user`(普通用户)。**管理 → 用户与权限 → 角色与功能**里可以建自定义角色,
按**功能点**勾选(例如 AI 助手、编码代理、深度检索、创建分享链接、导出数据……)。
一个功能点被关掉后:界面入口隐藏,服务端对应的能力也返回 403(不只是藏按钮)。
一个用户可以再单独覆盖角色的配额。

### 5.1 查看别人的知识库(只读)

「用户与权限 → 用户」列表里,每个别人的行尾有一个「查看」。点开后是一个全屏弹窗,里面就是这个人平时用的
工作台:文档树、预览、批注(只读)、任务、导入记录。它**复用同一套页面**,不是另做一套后台界面;
区别只有顶部的「只读查看」标识和所有写入口都消失。

- **谁能看**:角色里有 `sys.inspect`「查看他人知识库(只读)」的账号。这是独立功能点,和 `sys.users` 无关;
  管理员角色默认有,普通用户没有。自己的那一行不显示「查看」(直接去工作台),其他管理员可以互相查看。
- **部署开关**:

  ```toml
  [admin]
  inspect_enabled = true   # 关掉后前端入口消失,后端一律 403;只改了 config.toml 才生效
  ```

  这个开关不在「系统参数」页,避免误关之后还要去翻配置。关掉后 `/api/v1/auth/me` 会下发
  `admin_inspect_enabled = false`,已经打开的弹窗在下一次调用时也会被后端拒绝。
- **只读边界**:只放行读文档、读预览、读批注、读任务和导入记录的能力(后端维护一份 18 项白名单);
  保存、删除、移动、上传、版本恢复、分享、评论增删、取消 / 重跑任务、AI 与代理全部拒绝。
  界面不提供下载原件的入口;预览图片、PDF 等仍走 `/api/v1/raw`,但带上目标用户,不能换成管理员自己的库。
- **怎么认人**:前端每个请求带 `X-KB-Admin-View: usr_…`。这个头只认浏览器会话或**本人的 admin key**;
  普通访问令牌、MCP、agent.sock 带它一律 403(令牌不能借管理员的身份跨库)。它和分享用的
  `X-KB-Space` 互斥,同时出现是 400;目标用户 id 格式不对是 400,目标用户没有个人知识库是 404,
  想查看自己也会被拒绝。
- **审计**:打开弹窗记 `admin_space_view.open`;之后每次读取都把目标用户 id 写进 `args_json` 并落到
  `system.db` 的 `system_audit`,不是目标用户自己的库。目标用户不会收到通知,他的界面和会话也不受影响。
- **已知限制**:v1 没有「审计」页签;任务和导入记录靠轮询 / 手动刷新,不接目标库的实时 WebSocket;
  不提供下载原件;管理员如果直接用磁盘或本机 `kb.sock`,仍然能读到文件——这条通道约束的是接口行为,
  不是给服务器主人设防。

几个页面由功能点决定要不要出现(界面改版后的位置):

- **导入**页:「上传文件与附件」(`docs.upload`,普通用户默认有)。页签「导入记录」看每个文件的解析进度,「数据来源」管来源。
  普通用户在这里只有 4 种来源:网页、文件上传、压缩包、手写笔记。
- **管理 → 项目与集合**页:「服务器目录与 Git 来源」(`sources.local`,危险功能,默认只有管理员)。
  读服务器上的目录和外部 Git 仓库的来源只能在这一页的「服务器目录与 Git 来源」区块里添加(「添加来源」只列这两类)、同步和移除;
  导入页的来源列表、「全部同步」和「添加数据」里都没有它们,对任何账号都一样。给自定义角色勾上这个功能点,
  这个角色的账号也会在管理组里看到这一页,所以只给信得过的人。有这个功能点的账号在导入页的「数据来源」页签上会多一行指向「项目与集合」的提示,没有的账号看不到。
- 旧地址不会失效:`/sources` 跳到导入页,`/ingest`(解析队列)进「导入记录」,`/ingest/file/…`、`/ingest/<批次>` 跳到对应的详情页,书签和旧通知里的链接照常能打开。

## 6. 配额与资源保护

```toml
[quota]
storage_gb = 100            # 每人存储上限(含向量索引和代理工作目录);只是上限,不预占空间
max_upload_mb = 200
llm_tokens_per_day = 200000 # 每人每天大模型 token
acp_concurrency_total = 8   # 目前没有代码读取这一项,所以「系统参数」页和配额覆盖里都没有列它;全站名额实际看 §7 的 acp.toml(max_agents)
acp_concurrency_per_user = 1  # 同上(页面不列),实际看 acp.toml 的 max_per_user
acp_minutes = 30            # 同上(页面不列),一轮对话的时限实际看 acp.toml 的 turn_timeout_secs(默认 300 秒)
disk_reserve_gb = 30        # 整盘剩余低于它时停止所有人上传
links_per_user = 1000
friends_per_user = 1000
```

生效顺序:**全站默认 → 角色的 `quota_json` → 用户的 `quota_json`**,后者只覆盖它写了的键。
`index.parallel_slices`(默认 0 = 自动,核数的 1/4,最少 1、最多 4)限制全站同时跑几个**批量**索引分片,
一个人导入上万个文件不会让别人等几小时;交互式的编辑、保存不占这个名额。
管理员可以查看每个人的存储用量,以及大模型 token 的用量排行(能力 `llm_usage_overview`)。

## 7. AI 与编码代理

```toml
[ai]
enabled = true         # 总开关:关了,所有 AI 功能一起消失(入口隐藏、能力 403、后台提炼审核跳过)
extract = true         # 自动提炼与 AI 审核
deep_search = true
organize = true
assistant = true
acp = true             # 编码代理
chunk_context = false  # 用 LLM 给分块写上下文
```

- 大模型调用**按用户记账**,超过每日额度即拦截;每个人的用量排行在「管理 → 存储与用量 → AI 额度」页签。
- **编码代理(ACP)默认不给普通用户**(`ai.acp` 要管理员逐个授予)。授予之前请先看清它意味着什么:
  - 用户的代理跑在 bwrap 沙箱里:看不到别人的知识库、账号库、`secrets.toml`;只有自己的工作目录可写;
    丢掉全部 Linux capability、新会话、(内核允许时)独立用户命名空间——守护进程以 root 跑时也不能 `mknod`、`mount`
    或碰 `/proc/sys`;`prlimit` 限制 CPU 与文件大小;每人同时 1 个会话、全站同时 8 个(超出排队);
    工作区大小计入存储配额;事件只推给会话的主人。
  - **但代理要登录才能干活,而登录态在服务器上**:每个代理的配置目录(如 `~/.claude`、`~/.codex`)会以**只读**方式挂进沙箱。
    **被授予 `ai.acp` 的人在沙箱里 `cat` 就能读到这些登录凭据,以及这些目录里的历史会话。**
    这等于把你这台服务器上的代理账号借给他用。只授予信得过的人;不放心就不要授予,或者为这台服务器专门登录一个额度受控的代理账号。
  - **站点自己的 LLM key 不会交给普通用户的代理**(只给管理员自己的)。内置的 deepseek / openai / anthropic 代理对普通用户
    因此没有 key 可用,只有已经在配置目录里登录过的代理才能用。
  - **沙箱不隔离网络**:代理要访问模型接口,所以和宿主共用网络命名空间,能连到本机和内网的服务。
    如果这台机器上有只靠「来自 127.0.0.1」做信任的服务,请用防火墙限制。
  - **没有内存上限(没有 cgroup)**,见 §11。
- 管理员的会话保持原有行为(沙箱起不来时是否允许裸跑看 `allow_unsandboxed`)。
- **AI 助手页**(侧栏「AI 助手」,地址 `/assistant`)和顶栏 ⌘J 呼出的右侧抽屉是同一个组件,抽屉里的「全屏打开」进的就是这一页;
  宽屏(≥840 像素)左边常驻会话列表,手机上占满页面。入口需要功能点「AI 助手」(`ai.assistant`,普通用户默认没有)并且 AI 总开关开着,
  不满足时入口隐藏,直接输地址会看到「你的账号没有开通这个功能」。对话本身由外部编码代理完成(发送走 `acp_chat`),
  所以还要授予 `ai.acp`(见上面的风险说明),并且服务器上至少装好一个代理(管理 → 系统设置 → 编码代理),否则发送时提示「还没有可用的 ACP 代理」。
- **助手页输入框下面的额度行是「代理工作目录」,不是每日额度。**助手的对话走外部编码代理,不占内置模型的每人每天额度(§6 的 `llm_tokens_per_day`),
  会拦住用户的是下面这几项,键都在 `<KB_HOME>/acp.toml` 里(顶层键,改完不用重启,下一轮对话就按新值检查):

  ```toml
  workspace_mb = 512      # 每人代理工作目录上限(MB);0 = 不限
  max_agents = 8          # 全站同时会话数
  max_per_user = 1        # 每人同时会话数
  queue_wait_secs = 60    # 全站名额满了,最多排队等多少秒
  ```

  - **工作目录上限**:统计的是该账号 `spaces/<id>/agent-workspace/` 的总大小。输入框下面写「代理工作目录已用 X / 上限 Y」,用到 90% 提示「快满了」;
    超过上限后服务端拒绝开始新的一轮(「代理工作目录已用 … MB,超过上限 … MB,请先清理再继续」),页面上发送按钮置灰并写明原因,
    指到「个人设置 → 我的用量」看占用。上限为 0 时只写「已用 X」。服务端只对不在主知识库里的账号(`spaces/<id>/` 下的用户)检查这一项,不检查主知识库那一份。
    界面和能力里都没有清理代理工作目录的入口,所以用户超过上限后要管理员处理:调大 `workspace_mb`(下一轮就生效),或在确认可以删之后清理他的 `agent-workspace/`。
  - **名额与排队**:全站会话数到 `max_agents` 时,先回收别人空闲最久的会话;大家都在回答才排队,输入框上方显示「排队中:前面还有 N 个人,轮到你会自动开始」,
    最多等 `queue_wait_secs` 秒,超时提示「代理太忙了(全站最多同时 N 个),排队超时,请稍后再试」。自己已有会话时,空闲的旧会话先让位;
    旧会话还在回答就拒绝新的(「你已经有一个代理会话在运行,请等它结束或先关掉再开新的」)。
  - 设置页**没有**这些项(`workspace_mb`、`max_agents`、`max_per_user`、`queue_wait_secs`,以及单进程 CPU 秒数 `user_cpu_secs`、单文件大小 `user_fsize_mb`),只能改这个文件。
    文件写错(TOML 解析失败)时守护进程只在日志里警告「acp.toml 解析失败,用默认配置」,然后按默认值运行。
- 远程 MCP:每个用户用自己的令牌,经各自的 agent-socket 桥接,以**自己的身份**检索;
  令牌可选「包含共享给我的内容」。文件令牌仍对应本机超级用户,不要给别人。

## 8. 分享、协作与游客

```toml
[share]
allow_guest_view = true       # 不登录的游客能否打开分享链接
allow_guest_comment = false
allow_guest_edit = false
guest_link_gb_per_day = 10    # 每个游客链接每天的下载流量上限
room_max_users = 30           # 单个协作房间人数上限
```

- **授权角色**:查看者 / 评论者 / 编辑者 / 管理者。外人访问别人的资源得到 **404**(不泄露存在),
  权限不够的协作者得到 **403**。
- **分享链接**:令牌只在创建 / 重置时显示一次,库里只存哈希;可设有效期、4–12 位访问密码
  (连续输错 5 次锁 10 分钟)、是否允许下载。游客角色按 `[share]` **实时降级**(开关关掉后已有链接立即受限);
  游客编辑只保留 id / 版本 / 标题 / 正文。审计里游客的名字是 `guest:昵称#编号(经链接 …)`。
- **评论**支持回复(只有一层)、`@用户名` 提及和「已解决」:@ 只通知存在、账号可用、并且能看到这篇文档的人,其余静默忽略;
  回复会通知被回复的人(同时 @ 了他只发一条提及);游客可以评论但不能 @ 人,也不能标记已解决;删除一条评论会连它的回复一起删。
- 重置链接、给链接加密码或改密码之后,拿旧凭据连着的协作连接会在几秒内被断开(关闭码 4403);新凭据可以正常加入。
- 删除笔记或知识库时,它的授权和链接一并撤销。后台每小时清理一次过期链接和游客记录。
- **多人在线编辑**:同一篇文档有人同时编辑时,API 写入返回 409(不是排队覆盖);编辑内容定时落地到笔记,
  正文变了(例如被别的途径改过)协作草稿会作废。管理员在「存储与用量 → 分享链接」页签里列出和强制撤销全站的链接。
  界面上:点「编辑」就连上房间,标题上方的状态条显示『已同步 · 多人编辑中』和在线的人;断线后继续写,恢复后自动合并;
  点「完成」会先把最后的正文落地再回到阅读。**知识库页里的 Markdown 文件(.md 文件,不是笔记)用富文本编辑,不参与协作**;
  『共享给我』和公开链接里编辑同一个文件用的是代码编辑器,会和正在协作的人互相冲突(409),让大家先退出再改。

## 9. 两步验证(TOTP)

用户在「个人设置」里的「两步验证」卡片开启:重新输密码、扫码、输对第一个码才生效,同时给 8 个**只显示一次**的恢复码。
管理员可以替丢了设备的用户重置(同时作废他所有登录):能力 `user_totp_reset`。
`[accounts] require_admin_totp = true` 后,没开两步验证的管理级账号只能访问设置两步验证的接口,也不能关闭。
**上线前建议管理员账号先自己开上,再打开这个开关**,否则最后一个管理员会被锁在门外
(锁住时的应急:停服务,用 `kb user` 以外的手段无法绕过——需要从备份恢复 `system.db`,所以先开自己的)。

## 10. 日常运维

- 备份:`[backup]` 定时,账号库和每个用户的库都在内(§ `docs/BACKUP_RESTORE.md`)。恢复后经验条目的向量会自动补,
  项目文件要 `kb index <项目> --full`。
- 内存:守护进程用 jemalloc,空闲内存 1 秒还给系统;所有知识库共用一个有上限的向量库缓存
  (默认 512 MB 索引 + 128 MB 元数据)。release 构建实测:60 人在线、15 个协作房间约 1.0 GB;200 人在线、50 个协作房间、20 个同时上传约 1.7~2.0 GB,
  压测结束后基本不降(每个打开过的知识库带着自己的 SQLite 连接和向量库句柄)。部署机器内存建议 ≥ 8 GB。
- 压测:`KB_LOAD_USERS=… KB_LOAD_ONLINE=… cargo test --release -p kb-cli --features testkit --test loadtest -- --ignored --nocapture`。
  默认口径是「闭环」——每个在线用户发完一个请求立刻发下一个,检索约每人每秒 3 次、协作约每人每秒 4 次编辑,比真人重得多。
  `KB_LOAD_THINK_MS` 给每次请求后加等待(更像真人),`KB_LOAD_COLLAB_THINK_MS` 只给协作加。
  容量怎么读:200 人全闭环时检索 P95 约 7~9 秒(门槛 800 ms,未达标)。只让协作变稀疏(每次多等 3 秒)、检索仍然闭环,检索 P95 降到约 0.9 秒;
  所有操作都多等 3 秒(更像真人),检索 P95 约 0.6 秒,多等 10 秒约 0.3 秒。
  也就是说**瓶颈在高频协作更新**,不在检索本身;如果有人用脚本批量、高频地写协作文档,会拖慢全站其它操作。
  这是同一台机器上客户端与守护进程互相抢 CPU 的结果,每档只测了一次。
- 审计:游客操作、账号管理、授权变更、旧密码迁移都写入审计记录。
- **系统状态页**(管理 → 系统状态,功能点「备份、状态与全站审计」`sys.ops`;没有这个功能点的账号看到「你的账号没有开通这个功能」,页面不去读数据),
  分「服务 / 资源 / 组件 / 任务 / 日志」五页,每 10 秒自动刷新一次,右上角「刷新」可以手动读。**页面只显示后端的 `system_status` 真正返回的东西**,
  读不到的写「—」或「没读到」,不会用写死的文字顶替(旧版里写死的「工作线程状态」「任务吞吐与限流」「Nginx SSL / 443」「默认级别 INFO」,
  页面上并不存在的「诊断包清单」,以及拿三个负载值画的「走势图」,都已删掉):
  - 服务:版本、已运行时间、数据目录;集合 / 项目 / 数据来源个数;监听地址、是否允许远程访问、本机通道(socket)、MCP 接入方式与允许的访问域名;
    今日云端模型的调用次数和输入 / 输出用量(AI 总开关关掉后这张卡不出现,每个人的额度看「存储与用量 → AI 额度」)。页首的「需要注意」汇总没就绪的组件、磁盘偏紧和失败的任务数。
  - 资源:处理器(核数、启动以来的平均使用率、1 / 5 / 15 分钟负载)、内存、数据目录所在的磁盘、显卡,以及 NVIDIA / Intel 核显和已安装的命令行工具。
    内存和磁盘用到 80% 标「偏高」,90% 标「快满了」;磁盘到 90% 时管理员头像上也会出提醒(头像上的提醒一共三种:与后台服务的连接中断、备份失败、磁盘快满了)。
  - 组件:文字识别、音视频转写、索引模型、重排模型、云端模型、审核模型、模型运行服务各自是否就绪、当前用的是哪个;安装和更换在系统设置里。AI 总开关关掉后云端模型、审核模型两类不出现。
  - 任务:任务队列和导入队列各状态的个数,最近 8 个任务(AI 总开关关掉后不含自动提炼、自动审核)。
  - 日志:最近的警告和错误(错误和警告分开着色)、日志文件列表、最近 60 行日志(框内自己滚动)。要看更详细的日志,在服务器的 `config.toml` 里改 `[log]` 的级别,保存后热生效。
  - 各块互相独立:某一块读不到(字段缺失,或后端版本里没有这一块)时只有那一块显示「没读到」和「重新读取」,其它块照常;
    之后的自动刷新失败时保留上一次的数据,并写明「显示的是 12:30:05 的数据」,下一轮再试。旧链接 `?tab=overview`、`?tab=network` 会进「服务」页。
- **用户看到「服务暂时不可用」时**:浏览器在刷新页面、或登录状态缓存(5 分钟)过期后切页时,会先问一次后台的登录状态(`/api/v1/auth/status`);
  这一问连不上或返回了错误状态码,就进这个整页提示(地址 `/unavailable`),而不是被送去登录页(登录页同样连不上,用户只会看到一个不会好的登录框)。
  按原因分四种:返回 **503** 显示「服务正在维护」;返回其它错误状态码(例如 502、504)显示「服务出了点问题」;没有状态码(请求直接失败)显示「连不上服务器」;
  用户设备自己没有网络显示「你的设备现在没有网络」。前三种会自动重试:先等 3 秒,之后 6、12、24 秒,再往后每 30 秒一次,页面上写「已重试 N 次」;
  设备没有网络时不按时间重试,网络一恢复就马上试;任何时候都可以点「重试」。恢复后自动回到用户刚才要去的页面(只回站内地址,否则回首页),没登录的再去登录页。
  页面只把 503 当成「维护中」:想让用户在升级或重启期间看到「服务正在维护」,要让反向代理在后台不可用时回 503,回 502 / 504 的话用户看到的是「服务出了点问题」。
  用户停在某个页面不动时不会被换成这一页(登录检查只在切页时做)。
- **用户看到「找不到这个页面」时**:地址不对(输错、书签过期、页面搬了)会落到这一页,显示出错的地址;侧栏还在,可以点「回首页」、「去搜索」(账号没有「检索」`search.basic` 时没有这个按钮)
  或「返回上一页」(新开的标签页没有上一页就不显示)。没登录的人会先被带去登录页。旧版本的地址(`/dashboard`、`/browser`、`/sources`、`/ingest`、`/jobs`、`/projects`、`/system`、`/settings` 等)都有重定向,不会落到这里。
- **新用户引导**:账号里一条笔记都没有、而且没点过「不再显示」时,首页顶上会出现「欢迎!先从这几步开始」,每一步有「去做」入口,只列这个账号用得到的:
  写下第一条笔记(`docs.notes`)、导入已有的文件(`docs.upload`,已经有数据来源时标「已完成」)、试试搜索(`search.basic`)、邀请好友(`collab.friends`)、问问 AI 助手(`ai.assistant`,且 AI 总开关开着)。
  写下第一条笔记后卡片自动消失。「不再显示」只记在这台设备的浏览器里(按账号分开),换设备或清掉浏览器数据后会再出现,直到账号有第一条笔记。
- **快捷键表**:头像菜单 → 「快捷键」,或在没有输入框获得焦点时按 `?`;手机没有键盘,菜单里没有这一项,按 `?` 也不响应。表里有全局的按键(命令面板、收起 / 展开侧栏、「G 再按字母」跳转到首页 / 知识库 / 搜索 / 审核 / 任务 / 系统概览 / 评测)和页面里的按键(搜索页的 `/`、上下键和回车,编辑时保存)。

## 11. 已知限制(上线前请知悉)

- 网页来源默认**不能**抓内网 / 本机 / 云元数据地址(防止借服务器去读内网服务);确实要抓公司内网文档站时,
  在配置里设 `[network] crawl_allow_private = true`(要重启)。服务器目录与 Git 来源(界面在「管理 → 项目与集合」,见 §5)、`import_global` 要 `sources.local`
  (危险功能,默认只有管理员)。

- `allow_reshare`(链接的「允许再分享」)已存储但**未强制**。
- 本机设置页的『令牌』页签创建的令牌没有『包含共享给我』选项;需要的话在『个人设置』的令牌卡片里创建。
- 系统概览没有『在线协作房间数』:后端目前没有对应的能力。
- 批量撤销(`revert_batch`)改了正在协作编辑的**笔记**时,房间里的人会被请出去重新打开(关闭码 4409);撤销改的是**文件**时目前没有这一步,协作编辑中的文件请先让大家退出再撤销。
- 编码代理没有内存上限(没有 cgroup),只有 `prlimit` 的 CPU / 文件 / 进程数限制。
- 助手页在代理工作目录用满时置灰发送按钮,现在**只对服务端真的会拦的账号**(`spaces/<id>/` 下的用户)这样做(`acp_agents` 返回 `workspace_enforced`);主知识库账号只显示「代理工作目录已用 X」,不写上限也不置灰。边界与服务端一致:超过上限才拒绝,恰好等于上限只提示快满了。(旧版本里界面对所有账号都拦,主知识库账号会被无故挡住而服务端其实放行,已修;老守护进程没有这个字段时界面按不确定处理、不拦。)
- 笔记正在被多人编辑时,AI(内置助手、编码代理、MCP 客户端)想改正文不会被拒绝,也不会覆盖大家正在写的内容:改动会留成一条以「【AI 建议】」开头的评论;脚本和命令行得到 409。文本**文件**的保存(`save_file`)目前对 AI 也是 409。
- 管理员的「有未落地内容的文档」列表未做。
- 没有 WebAuthn / 短信验证码;只有 TOTP。
- 两步验证的密钥以明文存在 `system.db` 里(和密码哈希同库、同样 0600)。要还原才能算验证码,加密就得把密钥放在库外的文件里,
  而备份不含那个文件,恢复后所有人的两步验证会失效。所以:**备份归档要像对待密码库一样保管**(本机 `backups/` 在 0700 的数据目录里,
  归档与异地副本文件本身也是 0600)。
- 登录失败有两把锁:同一来源 1 分钟 5 次;同一账号 15 分钟 10 次(换 IP 也算)。被人故意输错会让账号暂时登录不了,
  15 分钟后自动恢复;管理员可以随时重设密码。
- 分享链接的访问密码短(4 位)时仍可能被慢速猜出:每个链接 10 分钟内全部来源合计输错 20 次就整体锁定,一天最多约 2900 次猜测。
  **重要内容请设 6 位以上的密码**。
- 评测(`eval`)现在每个知识库各一份,主知识库仍在 `<KB_HOME>/eval`;其它用户的评测目录(`spaces/<id>/eval`)不在备份里。
- 响应头:在 HTTPS 反向代理后面(带 `X-Forwarded-Proto: https`)时会加 `Strict-Transport-Security: max-age=31536000`(不含子域)。
